# GTST Exam Portal: Final Production Audit

**Audit date:** 2026-10-08 · **Scope:** student portal (repo root), `admin-frontend/`,
`backend/`, `backend/sql/` · **Target:** live mock exam, ~400 concurrent students

## Executive summary

The **code** is in good production shape. The architecture is sound: only the
backend touches the database, the server is authoritative for questions, timers and
scoring, and every exam write is a single row-locked database transaction. All
automated checks pass: 58 backend tests, 13 frontend unit tests, 6 Chrome
end-to-end scenarios, three clean builds, and a clean typecheck.

The audit made small, targeted fixes: admin polling hardening, a URL-length fix
for the dashboard at 400 students, a self-hosted face model, dead-code and
unused-dependency removal, corrected staging docs, and new deployment, API and
database documentation. No database schema, business logic, authentication or UI
behavior was changed.

**Deployment is blocked on operational items, not code.** Live Supabase
service-role keys and both JWT secrets were found in `backend/.env` inside the
project archive `GTST-EXAM-PORTEL.zip`. They must be rotated. Behavior at 400
concurrent students has been estimated but **not load-tested**.

> **BLOCKER — DO NOT DEPLOY YET:** rotate all four secrets (§ Security S1), then
> complete the staging checklist and a 400-student load test.

## Security findings

| ID | Severity | Finding | Status |
|---|---|---|---|
| S1 | **CRITICAL** | `backend/.env` holds live Supabase **secret keys** (`sb_secret_…`) for both projects plus both JWT secrets, and the **same file is inside `../GTST-EXAM-PORTEL.zip`**. The folder name looks like a GitHub archive, so the repository may contain it too. Anyone with these keys can read and modify all student data and the answer key, and forge student/admin tokens | **Open: manual.** Rotate all four (deployment guide §0). Delete or replace the zip. Check the git history of any repository it came from |
| S2 | MEDIUM | The project folder is **not a git repository**, so `.gitignore` does not protect a zip handover. `.env`, `node_modules/` and `dist/` end up in archives | **Open.** Hand over via git, or build the archive excluding git-ignored files |
| S3 | MEDIUM | The static frontend hosts set no security headers (CSP, HSTS, frame options). Helmet covers only the API | **Open.** Configure at the host or CDN (deployment guide) |
| S4 | LOW | Admin and student JWTs are kept in `localStorage`. An XSS would expose them. Mitigated: React escaping, no `dangerouslySetInnerHTML`/`eval`, admin tokens re-checked against `is_active` | Accepted |
| S5 | LOW | Admin login skips bcrypt for an unknown email, so a timing difference can reveal whether an email exists. Rate-limited to 10 per 15 min | Accepted |
| S6 | LOW | `npm audit`: `uuid` < 11.1.1 via `exceljs` (moderate). The bug triggers only when a caller passes a buffer to `uuid` v3/v5/v6, which `exceljs` does not do. The fix requires a breaking downgrade | Accepted |
| S7 | INFO | Build-time advisories in Tailwind 3's file watcher (`braces`, `micromatch`, …). **0 production vulnerabilities** in either frontend | Accepted (fix = Tailwind 4 migration) |

Verified secure: no service-role key or secret in any frontend source or built
bundle; no Supabase client in the browser; RLS on every table with no policies;
`EXECUTE` revoked from `anon`/`authenticated` on all 13 database functions;
CORS is an explicit allow-list (verified: foreign origin → 403); helmet headers on
the API; generic error messages (no stack traces, SQL or config); JWT secrets
validated at startup (≥ 32 chars, distinct); separate student/admin token types;
input validation (UUIDs, option letters, event types, message length);
content-sniffed uploads with size limits; private check-in photo bucket; per-student
rate limits (an exam hall sharing one IP is safe); no SQL string building.

## Deployment findings

- `VITE_API_URL` is baked in at **build** time for both frontends.
- The admin dashboard is built with `base: '/admin/'` and **must be served under `/admin/`**.
- The current `backend/.env` is a dev config: `NODE_ENV`, `STUDENT_ALLOWED_ORIGINS` and
  `TRUST_PROXY` are unset, and `ADMIN_ALLOWED_ORIGINS` is localhost. Production needs all of them.
- HTTPS everywhere (camera/microphone). SPA rewrites on both static hosts.
- No hosting platform config files are committed (no `vercel.json`, Dockerfile, …).
  The platform has not been chosen, so none were invented. The deployment guide gives
  the exact settings and an Nginx example.
- Every `localhost`/`127.0.0.1`/port reference is development-only (dev proxy,
  `import.meta.env.DEV` fallback, tests, docs). None reach a production build.
- After submission, students are redirected to `https://www.givelaurelsfoundation.com/`.
  This is intentional in code; confirm it is the desired destination.

7. Hosting: HTTPS, SPA rewrites, `/admin/` base path, `.wasm` MIME type and compression,
